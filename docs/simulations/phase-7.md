# Simulation matrix #4 — phase 7 exit

## Reading this report (hand-written; the rest is generated)

Phase 7's claim: *a block is periodized by its own data.* A block goal with an authored template
follows that template's bands, fitted over its working weeks. Every other block keeps the
generic envelope and says so. This report is matrix #3's grid (252 cells, week 2 of 8) plus a
week axis, **"Periodization by week"**, at the end. The week axis is where phase 7 shows.

**What holds.**
- The 252-cell grid has 0 per-cell flags: no planned day replaced, no redirect, no fallback-built
  session.
- On the week axis, each block follows its own periodization.
- `tests/test_simulate_matrix.py` pins both.

| block (8 weeks, deload every 4) | weeks 1-3 | week 4 | weeks 5-7 | week 8 | source |
|---|---|---|---|---|---|
| Running, distance | base RPE 4.0–6.0 ×1.00 | deload 5.0–6.5 ×0.50 | threshold ×2, race-specific | taper 5.0–7.5 ×0.55 | running |
| Running, sprint-primary | accumulation 6.5–7.5 ×1.15 | deload | intensification ×2, peak | taper 6.0–8.0 | generic |
| Calisthenics | prerequisites ×2, strength focus | deload | strength focus, skill ×2 | taper | calisthenics |
| Strength, HYROX | accumulation | deload | intensification ×2, peak | taper | generic |

**Findings.**

1. **A distance runner no longer gets a peak week.**
   - Before: accumulation at RPE 6.5–7.5, then a peak at 8.5–9.5 in week 7.
   - Now: base weeks at 4.0–6.0, and a race-specific week 7 at 7.0–8.5.
   - The deload week keeps the generic band, because the running template authors none. Its
     source is still `running`, since the block's plan owns it.
   - The taper uses the template's 5.0–7.5.
2. **A sprint-primary Running block stays generic.** It periodizes for Sprinting, which has no
   template. A distance runner's shape is not inherited.
3. **No prescribed load moved through periodization.** The envelope sizes load only for lifts with
   an e1RM code, and neither template's sessions use them. The one load change this phase is
   HYROX Strength Endurance's authored ceiling (phase 7.3). For an athlete with a squat e1RM, its
   cap is `min(7.0, envelope)`.
4. **Variants rotate by block week.** HYROX Simulation alternates Half A and Half B, and
   Running + Functional and Strength + Skill alternate the same way. So the grid's week-2 cells
   show the second variants. **Speed does not rotate:** `run_sprint` and `run_speed_endurance`
   never tie exactly, so scoring still picks `run_sprint`.
5. **Known, unchanged: the `min` column is the legacy `duration_min`.** The envelope's
   `volume_modifier` scales it for every session. That includes fixed-volume ones: a HYROX half
   simulation reads 57 min in accumulation and 25 in a deload week, although its structure (for
   time, one round) is fixed. The structure is the prescription, and this legacy field predates
   phase 7.
6. **Unreachable by design.** The Powerlifting, OlympicLifts, Grip, HalfMarathon and
   FullMarathon templates stay reference data until a block can declare those goals (ADR-0071).

### Why easy carries more dose than hard, in production

Not a workload bug: the workload preference does prescribe more sets for hard.
It is the v0 density variable. Production density is elapsed MINUTES PER SET, so
packing more sets into the same session lowers it and therefore lowers the dose —
adding work reduces the recorded training stress. Measured, 75-minute session:

| engine | 8 sets | 14 sets | ordering |
|---|---|---|---|
| v0 (production) | 2.89 | 1.55 | easy > hard — inverted |
| v1 (shadow) | 0.72 | 1.33 | hard > easy — correct |

v1 orders this example correctly and is uncalibrated, so for it the fix is phase
8B/8C activation rather than another change to the dose law. The example is a
Strength log: it does not show how v1 orders any other flagged session.
